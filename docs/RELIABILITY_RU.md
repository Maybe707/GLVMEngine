# Исправления после повторного аудита

Эти изменения дополняют предыдущий рефакторинг runtime, Windows backend и камеры.

## Пункты присланного аудита

| Пункт | Результат |
|---|---|
| 1. Переполнение компонентов | Ёмкость выводится из зарегистрированных массивов; заполненный чанк автоматически дополняется новым. Все списки результатов ECS динамические. |
| 2. Потеря компонента при удалении | Ручной switch удалён. Регистрация компонента задаёт типизированные операции переноса и очистки. |
| 3. Недопустимый ID | Проверки границ сохранены; добавлен учёт занятости ID, защита от повторного удаления, переполнения поколения и зарезервированного ID. |
| 4. Управление памятью vector | Хранение и время жизни делегированы `std::vector`; старые имена методов оставлены как адаптер. |
| 5. Звуковая очередь | Mutex, condition_variable, владение сэмплами, обработка ALSA/WinMM и остановка потока исправлены ранее; тесты сохранены. |
| 6. JSON | Границы, escape/Unicode и грамматика чисел исправлены ранее; регрессии сохранены. |
| 7. Vulkan | Извлечение исключений задач и пересоздание семафоров исправлены ранее; графические регрессии сохранены. |
| 8. Сборка | Один корневой Makefile, профили Debug/Release, зависимости от заголовков и флагов, перенаправление исторических Makefile, GitHub Actions Linux/Windows. |

## Дополнительные дефекты

- Поиск нескольких архетипов мог записать результаты поверх одного указателя.
  Запросы возвращают динамический список; движение и снаряды обрабатывают все чанки.
- Удаление соседних мёртвых сущностей пропускало объект, попавший на освобождённое
  место, и повреждало пространственные связи. Удаление теперь централизовано в World.
- Слоты инвентаря владели сырыми указателями без безопасного присваивания.
  Стандартные контейнеры исключают двойное освобождение при переносе компонента.
- Размещение предмета неправильно вычисляло строку в прямоугольном инвентаре;
  слишком большой предмет вызывал беззнаковое переполнение. Добавлены проверки
  размеров, исправлен индекс, сущность с ID 0 корректно считается занятой ячейкой.
- В коллизиях могли сохраняться указатели на `move` от предыдущего объекта,
  а внешние координаты превращались в недопустимые индексы. Используются локальные
  представления компонентов и общий безопасный расчёт диапазона ячеек.
- AABB игнорировал смещение центра меша и отрицательный масштаб. Расчёт границ
  объединён; предсказание движения соответствует смещению, применяемому физикой.
- Индекс данных игроков в кадре увеличивался один раз на чанк; теперь — на игрока.
- Анимация выбирала компоненты через ручной список масок; теперь использует
  зарегистрированные массивы и проверяет границы таблицы анимаций.
- Списки столкновений хранят полный ID с поколением: удаление и повторное
  использование номера не перенаправляет урон прошлого кадра в новый объект.
- Предметы внутри инвентаря исключаются из пространственной сетки и физики;
  после выбрасывания на землю снова индексируются.

## Архитектура и измерение

World и менеджер ID принадлежат экземпляру Engine, границы мешей — RenderAssets.
Системы получают зависимости в конструкторах. Пространственная сетка хранит
динамические обратные ссылки, обновляет изменившиеся сущности и сохраняет ёмкость
контейнеров. Ограничение в 32 ячейки на сущность устранено.

В локальном тесте диагностической Linux-сборки: 100 неподвижных сущностей,
1000 обновлений — около 5,6 мс; `updatedEntities == 0`, `visitedCells == 0`.
Это измерение CPU-регрессии, не обещание частоты кадров на других компьютерах.

## Регрессионное покрытие

`tests/ecs_system_tests.cpp`: 50 чанков, заполнение и повторное использование,
перенос вращения и владеющего памятью инвентаря, независимые миры, массовая гибель,
объект в более чем 32 ячейках, перемещение/удаление и обратные ссылки, NaN и выход
за границы мира, пустая сцена, движение во всех чанках, прямоугольный инвентарь,
слишком большой предмет, ID 0, масштабированные границы.

`make test` также сохраняет тесты JSON, аудио, камеры, контейнеров и архитектурных
границ. CI запускает CPU-тесты и компиляцию шейдеров; графическое взаимодействие
проверяется отдельно на машине с Vulkan и рабочим столом.
