# Нативный запуск GLVMEngine в Windows

Дважды нажмите **Run-GLVM.cmd** в корне проекта. Он сразу запускает
`build-win/GLVMEngine.exe`, без WSL, сборки при запуске и консольного окна.
Можно запускать `.exe` напрямую или создать обычный ярлык на него.
Не переносите один `.exe` из проекта: модели, звук и шейдеры нужны из соседних папок.

На этом компьютере используется **AMD Radeon RX 7900 GRE** через Windows Vulkan.
Первый короткий прогон на 120 кадров: инициализация около **0,91 с**, средняя частота
около **425 FPS**. Это измерение конкретного прогона при 1280×720; частота зависит
от сцены, размера окна и нагрузки компьютера. В WSL ранее использовался CPU llvmpipe.

Управление: WASD — движение, пробел — прыжок, I — инвентарь, O — коллизии,
мышь — камера, Esc или крестик окна — выход. При переключении на другое приложение
указатель освобождается. Окно можно изменять в размере и сворачивать.

Вертикальный поворот камеры доступен от −89° до +89° относительно горизонта.
Ограничение применяется к углу камеры: движение мыши не накапливается у границы,
поэтому обратный поворот начинается сразу. Горизонтальный поворот не ограничен.

Логи последнего запуска:

- `build-win/GLVMEngine.log` — выбранная видеокарта, время инициализации, события;
- `build-win/GLVMEngine-error.log` — ошибки.

Для короткого прогона:

```powershell
.\build-win\GLVMEngine.exe --frames 120
```

`Run-GLVM-WSL.cmd` сохранён для альтернативного Linux-режима и диагностики.

## Что исправлено в Windows backend

- Win32-окно корректно связывается со своим объектом с момента создания;
- закрытие, Esc, WASD, I/O, нажатия мыши и потеря фокуса обрабатываются без
  обращения к отсутствующему объекту события и повторных переключений от автоповтора;
- resize использует размер клиентской области, а сворачивание приостанавливает
  обработку кадров и сохраняет ресурсы при нулевом размере поверхности;
  время физического шага ограничено после длинной паузы;
- HWND/HINSTANCE передаются Vulkan, окно освобождается вместе с рендерером;
- звук использует очередь с ожиданием и WinMM, читает PCM WAV и отменяет
  проигрывание перед завершением потока; постоянного пустого цикла больше нет;
- общая очередь ввода больше не определяется внутри Wayland-модуля;
- путь к ресурсам определяется относительно `.exe`, а не каталога запуска;
- MinGW runtime статически связан: DLL компилятора и WSL для запуска не нужны.

## Сборка из исходников

Сборка выполняется в WSL, результат — нативный Windows x64 executable:

```bash
sudo apt-get install g++-mingw-w64-x86-64-posix mingw-w64-tools libvulkan-dev glslc
bash scripts/build-windows.sh
```

Скрипт использует Vulkan headers из Linux-пакета и создаёт import library для
установленного Windows `C:\Windows\System32\vulkan-1.dll`. В `build-win/sdk`
хранятся только производные файлы сборки. Установленный драйвер Radeon уже содержит
Windows Vulkan loader; отдельный Vulkan SDK для запуска не нужен.

Список общих исходников один для Windows и Linux. После изменения кода повторите
`scripts/build-windows.sh`; обычный запуск намеренно не компилирует проект.

## Проверки

```bash
bash scripts/build-windows.sh test-runtime build-win/windows_platform_tests.exe
bash scripts/build-windows.sh build-win/camera_tests.exe build-win/windows_camera_tests.exe
```

```powershell
.\build-win\runtime_tests.exe
.\build-win\windows_platform_tests.exe
.\build-win\camera_tests.exe
.\build-win\windows_camera_tests.exe
.\tests\windows_smoke.ps1
```

Проверяются порядок и владение системами, аудиопоток, независимость Vulkan-таблиц,
Windows WAV и отмена воспроизведения, нативное окно, два resize, события инвентаря
и коллизий, сворачивание/восстановление и закрытие. Тест камеры проверяет полный
вертикальный диапазон, обратный поворот у границы, реальное Win32-движение мыши
за пределами прежних 890 пикселей и возврат фокуса. Linux-регрессии также сохранены.
