# Исправления и проверка — 12 сентября 2026

Исходная версия: `Maybe707/GLVMEngine`, коммит `133cf64`.

## Что исправлено

- Linux Makefile: объекты текстур теперь действительно компилируются; объектные
  файлы находятся в build; отслеживаются зависимости заголовков; исправлена цель
  исполняемого файла и порядок линковки; шейдеры пересобираются после изменений.
- Ошибки Clang `-Werror` из-за неиспользуемых полей.
- Контейнер `vector`: разрушение последнего удалённого объекта, удаление из
  пустого контейнера, повторное использование после clear, границы итератора,
  сравнение со строками разной длины.
- HashMap: освобождение старых данных при присваивании, самоприсваивание,
  инициализация новых значений и поиск ключа в цепочке коллизий.
- JSON: ограниченный входным буфером разбор, проверка синтаксиса, экспоненты,
  экранирование, Unicode escape, повторная загрузка и ошибки отсутствующих файлов.
  Защищено самоприсваивание JsonValue.
- ECS: проверка несуществующего ID без чтения за границей массива, безопасное
  повторное удаление, сохранение поворота при swap-remove, поиск в нужном World,
  проверка фактической вместимости массивов компонентов.
- Пул потоков больше не зависает при запросе нулевого числа работников.
- Звук: порядок открытия/закрытия устройства и join потока, синхронизация очереди,
  ожидание вместо пустого busy loop, освобождение семплов и файлов, разбор PCM16 WAV,
  ошибки ALSA, отсутствие аудиоустройства; поддержка PulseAudio в WSLg.
- Wayland: безопасное закрытие через Esc и крестик, неблокирующая обработка
  событий, освобождение протокольных объектов и keymap fd, размер буфера курсора,
  удаление ненужного shared-memory буфера с неподдерживаемым WSLg форматом.
- Vulkan: отсутствующий vertex shader, реальное включение validation layer,
  лишние требования к display-расширениям, ожидание работников при завершении,
  смещения данных между кадрами в тенях/HUD/шрифтах/иконках и зависимости проходов.
- Resize: освобождение старых теневых ресурсов, сброс пула дескрипторов,
  пересоздание семафоров под число изображений, обработка нового размера Wayland.
- GPU-шейдеры: выход за границы таблицы виртуальных текстур при повторяющихся UV,
  недопустимые индексы костей, фоновое освещение в тенях, лишнее гамма-преобразование
  перед записью в sRGB swapchain.
- Кэш моделей: создание отсутствующей папки, точное сравнение пути, чтение строк
  только после проверки чисел, поддержка пробелов в новых записях.
- Добавлены Windows-запускатель и воспроизводимые команды сборки и проверки.

## Проверено

- `make -f MakefileLin test`: шесть отдельных регрессионных сценариев контейнера,
  сущностей и потоков, а также группы JSON/HashMap/аудио и ECS World.
  Исходные шесть сценариев падали; исправленная версия проходит ASan/UBSan.

- 300 кадров демосцены под ASan/UBSan и Vulkan synchronization validation:
  отрисованы все кадры, нет ошибок доступа к памяти и нарушений синхронизации.
- `tests/renderer_probe.py`: два изменения размера, инвентарь, слой коллизий,
  18 кадров и завершение; проверка через linker wrapping, без тестовых веток в игре.
- Оптимизированная версия: сборка, загрузка сцены, завершение после заданного числа кадров.
- Реальный кадр сохранён средствами Mesa и просмотрен.

## Особенности среды

Ubuntu 26.04 / Clang 21 / Mesa 26.0.8 / WSLg, Vulkan llvmpipe на CPU.
При обычной выгрузке Mesa LeakSanitizer сообщает о 240 байтах из её библиотек.
Прогон с закреплённой библиотекой драйвера заканчивается без отчётов об утечках;
проверка утечек не отключается:

```bash
export LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libvulkan_lvp.so
export VK_DRIVER_FILES=/usr/share/vulkan/icd.d/lvp_icd.json
bash tests/gpu_smoke.sh
python3 tests/renderer_probe.py
```

Пути выше относятся к этой Ubuntu x86-64. В обычном запуске через Run-GLVM.cmd
эти переменные не задаются, выбор Vulkan-драйвера остаётся автоматическим.

Это перечень воспроизведённых и исправленных дефектов. Проверка не доказывает
отсутствие всех возможных ошибок движка: другие GPU, Windows/MSYS2, X11/XCB,
OpenGL, сетевой режим и произвольные сторонние модели не проходили полный прогон.
